I accept both challenges and the detector-control findings. Ratified phase bytes are
immutable per run. Founder plus distinct Validator may ratify a superseding phase,
which always creates a new run/generation and invalidates unstarted manifests. An
in-flight run either completes under retained old bytes or aborts and remains; it
never absorbs the amendment. Unimplementable/expensive obligations are failures or
new-run decisions, not silent edits.

Every V-1..V-9 gate now freezes positive control, negative control, threshold, and a
detector mutation before code combination. A positive control miss is
INVALID_HARNESS. V-3 plants canaries in every encoding/surface including packed Git
and SQLite blobs before trusting the clean scan. A second implementation-blind
Detector Reviewer reviews Tester artifacts. V-2 uses two independent gold annotators
and kappa >=0.80 before adjudication freeze.

Benchmark repositories are founder-owned or permissively licensed public code with
provider-transmission rights recorded in the manifest; no customer/private repo is
eligible absent separate owner authorization. Worktrees, agent homes, transcripts,
raw Git history, and tool logs are private run evidence, mode 0700, sanitized then
deleted within 24 hours absent an incident hold. Consent withdrawal destroys raw
copies and appends RETIRED_DATA_WITHDRAWN, making the result noncurrent; a manifest
never overrides data rights.

Authority is exact-scope, not a prestige lattice. Founder owns product/experiment
intent and answers architecture only if separately registered. Two active overlapping
authorities are a steward-owned registry conflict; neither answer wins. The same
authority changes an answer only by explicit parent-bound supersession; an
unparented contradiction stays conflict. Recency never resolves either case.
